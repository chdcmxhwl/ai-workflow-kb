# n8n：节点式工作流自动化平台

资料来源：GitHub 仓库 n8n-io/n8n 的 README.md，仓库地址 https://github.com/n8n-io/n8n 。抓取日期 2026 年 11 月 12 日，当时仓库星标约 21 万。本文依据原始 README 整理为中文，保留项目自述的能力划分与许可表述。

## 一、项目定位与名称

n8n 自述为「面向 AI 智能体与工作流自动化的平台」，采用 fair-code 模式。它把可视化画布与自定义代码结合起来，既可以在本机自托管，也可以使用云服务，并连接 1500 多个集成。README 用一句话概括其目标：让用户能够把原型一路带到生产环境，用可视化方式构建 AI 智能体与多步骤工作流。

关于名称，README 专门解释过：n8n 取自 nodemation，读作 n-eight-n。这个说法也提示了它的基本组织单位就是节点与连线。

## 二、README 列出的关键能力

**1. AI 原生的自动化平台**。使用自己的数据、模型与工具构建并运行 AI 工作流和多步骤智能体。

**2. 模型灵活性、不被锁定**。可以接入 OpenAI、Anthropic、Google 或开源模型，更换服务商时不需要改动整体架构。

**3. 从原型到生产**。设计带逻辑判断、工具调用、人工审批与完整可观测性的多步骤 AI 工作流。

**4. 需要时再写代码**。可视化搭建可以与 JavaScript、Python 以及 npm 包结合，用来处理更高级的自动化逻辑。

**5. 企业级能力**。支持自托管与安全部署，提供基于角色的访问控制、审计轨迹以及对敏感数据的支持。

**6. 复用已有资产**。提供 1500 多个集成与 9000 多个工作流模板，把 AI 能力接入已有系统。

## 三、可视化画布、代码节点与人工审批

n8n 的编排方式是把触发、处理、判断、输出做成画布上的节点，用连线表达数据流向。README 特别强调可视化与代码并不互斥：常规步骤用节点配置完成，复杂逻辑再落到 JavaScript 或 Python 代码节点。这一点与纯粹的图形化工具不同，也与本平台的做法相近——本平台同样提供代码节点，默认以 Python 执行临时脚本，也可切换为 JavaScript 调用 node。

人工审批被列在「从原型到生产」一项里，属于流程控制能力：自动化流程可以在关键环节停下来等待人来确认，再继续执行。本平台与之对应的能力是「提问」节点，运行时向使用者提问，拿到回答后再继续。两者都说明节点式工作流不只是自动执行，也可以把人放进流程里。

## 四、自托管与许可模式

n8n 支持自托管部署，README 给出的快速启动方式依赖 Docker，编辑器默认在 localhost:5678 访问。许可方面采用 fair-code，按 Sustainable Use License 与 n8n Enterprise License 分发：源码始终可见，可以任意自托管，可以扩展自己的节点与功能；部分企业级功能另需商业许可。

## 五、对答辩演示的参考价值

n8n 适合作为「节点式可视化编排」这一形态的公开参照。它说明把流程拆成节点、用连线组织执行顺序、在必要时插入代码与人工审批，是一类被大规模使用的工程做法。本平台的画布、22 种节点分组、条件判断与提问节点，与这一类平台共享相同的编排思路；差别在于本平台把重点放在本地优先、离线可跑，以及大语言模型节点与确定性节点混合编排上。
