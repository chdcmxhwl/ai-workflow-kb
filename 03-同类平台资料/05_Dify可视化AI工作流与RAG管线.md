# Dify：可视化 AI 工作流与 RAG 管线

资料来源：GitHub 仓库 langgenius/dify 的 README.md，仓库地址 https://github.com/langgenius/dify 。抓取日期 2026 年 11 月 12 日，当时仓库星标约 16.1 万。本文依据原始 README 整理为中文，保留项目自述的术语与能力划分。

## 一、项目定位

Dify 是一个开源的 LLM 应用开发平台。README 的表述是：直观的界面把 AI 工作流、RAG 管线、智能体能力、模型管理以及可观测性能力整合在一起，让应用能够从原型快速走向生产。可观测性方面提到 Opik、Langfuse 与 Arize Phoenix 等工具的集成。平台既提供云版本 Dify Cloud，也提供可自行部署的社区版 Dify Community Edition，另有面向企业的 Dify Enterprise。

## 二、README 列出的七项核心能力

**1. 工作流 Workflow**。在可视化画布上构建并测试 AI 工作流，这是 Dify 最核心的使用方式。

**2. 全面的模型支持**。接入数十家推理服务商提供的数百种商业或开源大语言模型，覆盖 GPT、Mistral、Llama3，以及任何兼容 OpenAI API 的模型，同时支持自托管方案。

**3. 提示词 IDE**。提供编写提示词的界面，可在同一处比较不同模型的表现，并为对话类应用添加文本转语音等附加能力。

**4. RAG 管线**。覆盖从文档摄入到检索的完整链路，开箱支持从 PDF、PPT 等常见文档格式抽取文本。

**5. 智能体 Agent**。智能体拥有自己的沙箱，可以运行命令、安装软件、处理文件，以完成开放式任务；可以描述想要的智能体让它自行构建，也可以给它配置技能、接入 Dify Marketplace 的工具、MCP 服务器或自有 API，并把它作为对话应用或工作流中的一个步骤来使用。

**6. LLMOps**。持续监控与分析应用日志和运行表现，依据生产数据与人工标注不断改进提示词、数据集和模型。

**7. 后端即服务**。上述能力都配有对应 API，便于把 Dify 集成进自己的业务逻辑。

## 三、RAG 管线与知识库的配合方式

RAG 管线是 Dify 与知识库检索直接相关的一环。README 把它的范围界定为「从文档摄入到检索」：先把 PDF、PPT 等格式的文档抽取成文本，再在应用运行时按查询检索相关资料，交给大语言模型生成回答。知识库因此不是独立的资料夹，而是工作流中被检索节点或智能体调用的一项资源。

这与其他可视化工作流平台的做法一致：把「检索」做成流程中的一个环节，让模型在生成之前先获得可引用的资料，而不是仅凭参数记忆作答。差异在于检索算法与文档组织形式，各平台实现并不相同。

## 四、与本平台的对照

本平台同样采用可视化画布与固定输出变量，README 中明确写到变量系统是「Dify 风格」的，每个节点产出固定变量名，下游按名字引用。两者都把工作流、模型管理、知识检索与智能体放在同一套界面里。

区别主要在运行形态与检索实现。Dify 以服务端部署为主，最小部署要求为 2 核 CPU、4 GiB 内存，通过 Docker Compose 启动；本平台是本地优先的桌面应用，数据存于本机 SQLite。Dify 的 RAG 管线是其平台能力的一部分，本平台的知识库则明确采用零依赖的 BM25 词法检索，中文按单字与二字组切分，每块约 500 字、重叠 60 字，检索全程离线完成。答辩中可以据此说明：同样是可视化 AI 工作流，编排理念接近，但落地形态与检索机制可以按场景取舍。
