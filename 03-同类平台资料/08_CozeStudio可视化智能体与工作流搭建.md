# Coze Studio：可视化智能体与工作流搭建

资料来源：GitHub 仓库 coze-dev/coze-studio 的 README.zh_CN.md 与 README.md，仓库地址 https://github.com/coze-dev/coze-studio 。抓取日期 2026 年 11 月 12 日，当时仓库星标约 2.2 万。本文依据仓库自带的中文 README 整理，保留原文的功能划分与部署表述。

## 一、项目定位

Coze Studio 是一站式 AI Agent 开发工具，提供大模型与工具、多种开发模式和框架，覆盖从开发到部署的全过程。中文 README 明确指出，它源自服务上万家企业与数百万开发者的「扣子开发平台」，开源的是其核心引擎。通过可视化设计与编排工具，开发者可以用零代码或低代码方式快速创建和调试智能体、应用和工作流，实现 AI 应用开发和定制化的业务逻辑。

项目把「降低 AI Agent 开发与应用的门槛」写进定位说明，并鼓励社区共建。这与可视化工作流编排平台面向非专业开发者的取向一致：把编排能力从代码移到界面上。

## 二、四项核心技术与功能清单

README 列出 AI Agent 开发所需的四项核心技术：Prompt、RAG、Plugin、Workflow。四项技术并列，说明工作流只是其中一环，提示词、知识库、插件与流程编排共同构成智能体开发的基础。平台提供应用模板与编排框架，使开发者可以直接在模板上构建智能体。

功能清单按模块划分：模型服务负责管理模型列表，可接入 OpenAI、火山方舟等在线或离线模型服务；搭建智能体支持编排、发布、管理智能体，并可配置工作流、知识库等资源；搭建应用支持创建与发布应用，通过工作流搭建业务逻辑；搭建工作流支持工作流的创建、修改、发布与删除；开发资源支持创建并管理插件、知识库、数据库、提示词；API 与 SDK 提供创建会话、发起对话等 OpenAPI，并可通过 Chat SDK 把智能体或应用集成进自有系统。

## 三、技术架构与部署

后端采用 Golang 开发，前端使用 React 与 TypeScript，整体基于微服务架构，并遵循领域驱动设计 DDD 原则构建，目标是提供高性能、易扩展、便于二次开发的底层框架。最低环境要求为 2 核 CPU、4 GB 内存，需要预装 Docker 与 Docker Compose；部署后在 localhost:8888 注册账号、配置模型服务，再访问主界面。README 明确提示：部署到公网前需评估账号注册、工作流代码节点的 Python 执行环境、服务监听地址、SSRF 以及部分 API 水平越权等安全风险。

这条安全提示对答辩有参考价值：只要工作流里允许用户写脚本，代码节点就不只是功能点，也是需要约束的执行边界。本平台同样提供代码节点，默认以 Python 执行临时脚本，因此在本地优先的运行形态下，把执行范围限制在本机是合理的取舍。

## 四、与节点式编排平台的对照

Coze Studio 的「搭建工作流」与「搭建智能体」分开列为两个模块，智能体可以挂接工作流与知识库作为资源；本平台则把智能体直接做成画布上的一类节点，与知识检索、代码、条件判断、循环、并行等节点并列，由连线统一表达执行顺序。前者是资源挂载式，后者是节点编排式。

两者都把模型配置作为独立环节：Coze Studio 在部署后需先到模型管理页新增模型，否则搭建智能体、工作流和应用时无法选择模型；本平台在模型配置页维护多套配置，工作流节点只引用配置标识，更换模型不需要改动画布。共同点是模型与编排解耦，区别在于资源组织方式。
