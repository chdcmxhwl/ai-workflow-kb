# AI 工作流编排平台：节点体系与知识库机制

资料来源：项目自述文档 README.md（仓库地址 https://gitee.com/UtroYAKQ/ai-workflow），并与本地源码 KnowledgeService.ts、database.ts 核对。整理日期 2026 年 11 月 12 日。本文为中文整理稿，用于知识库检索演示，术语与项目实现保持一致。

## 一、平台定位

AI 工作流编排平台是一个本地优先的桌面应用，目标是把调用大模型这件事变成可复用、可编排、可协作的工作流。应用内置可视化编辑器，基于 React Flow 提供拖拽式节点画布，界面文案全部使用中文。执行时从唯一的「开始」节点出发，顺着连线逐个执行节点，由条件判断节点负责分流，直到「结束」节点。大语言模型、代码、工具调用、条件分支、知识检索、多智能体协作都作为节点串在同一张图上。数据默认落在本机，不强制上云。

## 二、22 种节点的五层分组

应用目前提供 22 种节点，按用途分成五组。

基础编排共 6 种。**1. 开始**，工作流起点，定义输入变量，每条工作流有且只有一个。**2. 结束**，工作流终点。**3. 条件判断**，按条件分出「是」与「否」两条边。**4. 赋值器**，用于变量赋值。**5. 模板转换**，用模板字符串渲染文本。**6. 提问**，运行时向使用者提问，拿到回答再继续执行。

模型与文档共 7 种。**1. 大语言模型**，调用模型生成回复，可选把输出按 JSON 解析注册成变量。**2. 图片理解**，把图片送进多模态模型解读。**3. 读取文档**，解析 Word、PDF、Excel 等文档内容。**4. 代码**，执行脚本，默认 Python，写成临时文件后调用 python，也可切换为 JavaScript 并调用 node。**5. 工具**，调用内置工具或 MCP 服务器上的工具。**6. 网络请求**，发起 HTTP 请求。**7. 调用工作流**，把另一条工作流当作一个节点运行，支持传参与回收结果。

流程控制共 4 种，分别是循环、并行、合并、延时。循环对一个集合逐项调用子工作流并汇总每轮结果；并行把一批任务并发跑完再汇总；合并把多路结果收进同一个列表并按设定顺序排列；延时等待若干秒再继续，常用于错开调用节奏。

数据与通知共 3 种。文件节点读写本地文件，返回路径、内容与大小；通知节点向外部渠道推送消息；文本处理节点对文本做截取、拼接、计数等轻量变换。

智能增强共 2 种。知识检索节点按查询从知识库取出相关资料，拼成上下文喂给下游节点；智能体节点是带角色设定与协作能力的模型节点，可以点名递话、读写共享工作区。

上述 22 种节点里，真正调用大语言模型的只是其中一部分，代码、条件判断、文件、文本处理、循环、并行等节点由执行引擎确定性执行，不依赖网络与模型密钥。新增一类节点不需要改动执行引擎，只要在扩展点登记即可。

## 三、变量系统与模型执行层

平台采用 Dify 风格的固定输出变量，支持作用域嵌套。每个节点产出固定的变量名，下游节点按名字引用，避免自由格式的上下文拼接。大语言模型节点支持三种执行方式：builtin 内置工具循环、opencode 本地 OpenCode 服务、cli-agent 命令行智能体。新增一种执行方式只需登记一条目录项，模型配置与画布编排相互独立，更换模型不需要改动工作流结构。平台还支持连接 MCP 服务器，兼容 Stdio 与 SSE 两种模式，自动加载对方提供的工具以扩展工作流能力。

## 四、知识库的导入、分块与 BM25 检索

知识库负责把课件、复习题、作业等文档变成模型可引用的资料。导入方式有两种：从本地选择文件导入，或在页面直接粘贴文本。导入后系统按段落贪心合并分块，每块目标长度 500 个中文字符，相邻块保留 60 字重叠，避免一句话从中间被劈断。全文收下不截断。

检索采用零依赖的词法 BM25，不装向量模型、不联网。分词规则是英文与数字按 ASCII 词切分，中文连续段同时切出单字与二字组，例如「机器学习」会拆出「机器」「器学」「学习」，查询命中任意一个子串都有贡献。BM25 的词频饱和参数 k1 取 1.5，长块惩罚参数 b 取 0.75，默认返回最相关的 5 块。数据库表中预留了 embedding 列，接入向量模型时把向量存入该列并替换检索器即可，上层节点与页面不用改动。

工作流中的知识检索节点按查询取出资料拼成上下文，直接喂给下游的大语言模型节点；大语言模型节点自身也能通过内置的 knowledge_search 工具决定该查什么。知识库页面负责导入文档、删除文档、查看分块明细与测试检索。整个检索过程在本机完成，文档不出本机。需要说明的是，BM25 是词法检索而非语义检索，命中依赖字面重合，因此主题集中的短文档比内容混杂的长文档更容易被准确召回。

## 五、问答路由、场景模板与评测闭环

问答首页不把用户问题直接交给模型作答，而是先由模型从工作流库中判断该调用哪一条流程，交给子流程执行，再把流程产出整理成回答。若库中没有合适流程，模型会在判断节点输出一份流程设计，系统把这条流程真实写入工作流库并在本轮立即执行，同类需求再次提出时即可复用。

平台内置八套面向高校教育场景的工作流模板，一键导入后自动跳到画布并选中该工作流。模板刻意不使用循环、并行这类依赖子流程的节点，保证导入后立刻可运行。评测与自优化闭环给工作流挂上测试用例批量跑分，按硬规则与模型裁判双路评分；系统能针对未通过的用例改写提示词，并用留出集验收改动是否真的有效。

## 六、本地存储与页面构成

整库存于本机 SQLite，使用 sql.js 的 WASM 版本，每次写入后整库导出回写磁盘，适合数据不出本地的场景。工作台包含问答首页、工作流画布、场景模板、评测优化、运行历史、知识库、模型配置、MCP 配置、技能配置、规则库、设置等入口。

## 七、与同类开源平台的关系

Dify、n8n、LangGraph、Coze Studio 都是可视化工作流编排或智能体编排领域的开源项目，各自侧重不同：Dify 强调 AI 工作流与 RAG 管线，n8n 强调通用自动化与大量集成，LangGraph 强调有状态智能体的低层编排框架，Coze Studio 强调零代码或低代码的智能体与工作流搭建。本平台同样是节点式画布，但把重点放在本地优先存储、确定性节点与模型节点混合编排、知识检索与评测闭环上，适合在课堂与答辩环境中离线演示。
